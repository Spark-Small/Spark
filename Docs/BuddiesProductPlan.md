# 搭子 Tab 产品方案

> **核心只有一句话：找人玩。**  
> 不花钱找人玩 = 同好；花钱找人玩 = 预约。两条路径，同一件事。  
> 活动 Tab 卖「场」；搭子 Tab 卖「人」。

---

## 1. 第一性原理

面向几千万～几亿用户时：

| 错误做法 | 为什么错 |
|--|--|
| 产品预置「今晚运动 / 一起吃饭…」场景树 | 覆盖不全；运营改类目成本高；用户真实意图远比枚举丰富 |
| 首页先选场景再出人 | 多一跳，且用模型样本心智做大众产品 |
| 搭子页堆活动卡 | 和活动 Tab 抢戏，稀释「找人」 |

| 正确做法 | 为什么对 |
|--|--|
| **人是一等公民** | 列表直接见人、见状态、见距离 |
| **意图来自用户** | `lookingFor` / 兴趣标签 / 搜索词，开放域 |
| **排序与筛选可扩展** | 推荐 / 附近 / 刚活跃；筛选 Sheet 收细条件 |
| **付费只是找人的一种结算方式** | 同一「找人玩」，预约多价、档、认证、履约 |

**结论：不需要、也不应该用少数产品定义场景去覆盖全量用户。**  
场景若出现，应是数据涌现的趋势（搜索热词、城市热意图），不是写死在客户端的 4～8 个磁贴。

---

## 2. 双路径（唯一分段）

```
找人玩
├─ 免费（同好）  打招呼 / 邀约去某场
└─ 预约（花钱）  选档期 / 支付 / 履约
```

顶栏分段文案：**免费 | 预约**（对内可仍用 `BuddyKind.free / .paid`）。

---

## 3. 信息架构（规模化）

### 顶栏

| 位置 | 内容 |
|--|--|
| 大标题菜单 | **免费 \| 预约**（`platformTabRootTitleMenu`，对齐活动分类菜单） |
| Trailing | **搜索**（按需唤起，首页无常驻 drawer）+ **筛选** |
| 陪玩预约 | **仅**「我的 → 陪玩预约」（含待处理数量） |
| 细条件 | **仅**筛选 Sheet（排序 / 仅可约 / 服务类型 / 地区…）；首页无 chip 条 |

### 免费

```
精选横滑（无标题，≤4）
有信号辅轨（≤2：附近 / 同频 / 今晚有空 / 接着逛）
双列人墙（剩余全部）
兴趣圈子（次要）
```

无产品场景磁贴。无假组局人数。无空壳「发起邀约」。辅轨跨轨去重；无信号不出轨。排序默认推荐；刚活跃仅在筛选。

### 预约

```
精选横滑（无标题）
推荐榜（日/周/月 + 快捷长条 → 打开筛选或进厅）
更多陪玩双列墙（剩余全部）
语音厅（次要）
```

页内不用 chip；比价排序 / 仅可约 / 服务类型只在筛选 Sheet。发现卡主操作统一「选档期」+ `activityPrimaryCTA`。

## 4. 卡片决策信息

### 免费找人

- **双列照片卡**为主：封面、距离/共同兴趣角标、在线、我想…、匹配理由、打招呼  
- 顶栏压缩：想找 → 排序 chip → 搜 → 筛选  
- 不要：字母圆头像列表、假组局、空壳邀约  

### 花钱找人

- 横排：左封面右价/档/响应；**整宽选档期**（不把 CTA 塞照片底下）  
- 分区文案用「预约陪玩」，避免「花钱找人玩」的生硬感  

---

## 5. 商业与信任（摘要）

- 货币化在「预约」路径：成交抽成、会员提效、认证曝光  
- 信任与退改挂在预约购买路径  
- 详见下文历史章节；实现见工程对照  

---

## 6. 分阶段

### 已落地（对齐「找人玩」+ 与活动同 chrome）

- 大标题菜单切 **免费 \| 预约**；Trailing **搜索 Sheet + 筛选**；首页无 `.searchable` drawer  
- 陪玩预约入口只在 **「我的」**（待处理数量）；发现顶栏不再放预约  
- 页面壳：`discoverBrowseScrollChrome` + `discoverBrowsePageColumn`（与活动同间距）  
- 筛选 Sheet 唯一收纳：排序、仅可约、服务类型、地区…；首页无 chip  
- Catalog：精选 + ≤2 有信号辅轨 + 全量人墙；今晚档用 `BuddyScheduleSlot`  
- 发现 CTA：`activityPrimaryCTA` / `activitySecondaryCTA`；主操作文案「选档期」  
- 辅轨「查看全部」  

### 后续（数据层）

- 热搜 / 城市热意图由服务端下发，客户端不写死类目树  
- 个性化排序；冷启动用附近 + 活跃，不用假场景
