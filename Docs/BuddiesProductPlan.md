# 搭子 Tab 产品方案

> **核心只有一句话：找人玩。**  
> 不花钱找人玩 = 同好；花钱找人玩 = 预约。两条路径，同一件事。  
> 活动 Tab 卖「场」；搭子 Tab 卖「人」。

---

## 1. 第一性原理

面向几千万～几亿用户时：

| 错误做法 | 为什么错 |
|--|--|
| 产品预置「今晚运动 / 一起吃饭…」场景树 | 覆盖不全；运营改类目成本高；用户真实意图远比枚举丰富 |
| 首页先选场景再出人 | 多一跳，且用模型样本心智做大众产品 |
| 搭子页堆活动卡 | 和活动 Tab 抢戏，稀释「找人」 |

| 正确做法 | 为什么对 |
|--|--|
| **人是一等公民** | 列表直接见人、见状态、见距离 |
| **意图来自用户** | `lookingFor` / 兴趣标签 / 搜索词，开放域 |
| **排序与筛选可扩展** | 推荐 / 附近 / 刚活跃；筛选 Sheet 收细条件 |
| **付费只是找人的一种结算方式** | 同一「找人玩」，预约多价、档、认证、履约 |

**结论：不需要、也不应该用少数产品定义场景去覆盖全量用户。**  
场景若出现，应是数据涌现的趋势（搜索热词、城市热意图），不是写死在客户端的 4～8 个磁贴。

---

## 2. 双路径（唯一分段）

```
找人玩
├─ 免费（同好）  打招呼 / 邀约去某场
└─ 预约（花钱）  选档期 / 支付 / 履约
```

顶栏分段文案：**免费 | 预约**（对内可仍用 `BuddyKind.free / .paid`）。

---

## 3. 信息架构（规模化）

### 顶栏

| 位置 | 内容 |
|--|--|
| Leading | 筛选（地区 / 性别 / 距离 / 兴趣…） |
| Principal | **免费 \| 预约** |
| Trailing | 我的预约（未完成角标） |

### 免费

```
我也想找…（用户自填状态）
搜一搜（开放域）
排序：推荐 | 附近 | 刚活跃
人列表（我想… + 为什么推你 + 打招呼）
兴趣圈子（次要）
```

无产品场景磁贴。无假组局人数。无空壳「发起邀约」。

### 预约

```
品牌头「搭子·陪玩」
意图入口：运动 / 聊天 / 线下 / 活动（从擅长与服务类型涌现，非游戏品类树）
Hero 匹配条 → 立即匹配
排序：推荐 | 价格 | 最早可约 + 仅可约
热门推荐横滑
快捷：快速匹配 / 语音派对 / 线下搭子
擅长分类 chip
陪玩师排行榜（日/周/月）
更多服务者列表
语音厅（次要）
```

详情：分段「服务 | 资料 | 评价」；底栏「私信 + 快速下单」。评价为履约反馈演示，信任档案仍在「资料」。

---

## 4. 卡片决策信息

### 免费找人

- **双列照片卡**为主：封面、距离/共同兴趣角标、在线、我想…、匹配理由、打招呼  
- 顶栏压缩：想找 → 兴趣快开 → 搜 → 排序（不再堆大标题）  
- 不要：字母圆头像列表、假组局、空壳邀约  

### 花钱找人

- 横排：左封面右价/档/响应；**整宽选档期**（不把 CTA 塞照片底下）  
- 分区文案用「预约陪玩」，避免「花钱找人玩」的生硬感  

---

## 5. 商业与信任（摘要）

- 货币化在「预约」路径：成交抽成、会员提效、认证曝光  
- 信任与退改挂在预约购买路径  
- 详见下文历史章节；实现见工程对照  

---

## 6. 分阶段

### 已落地（对齐「找人玩」+ 提速匹配）

- 分段免费 / 预约；开放搜索跨模式保留  
- 「我也想找」+ 兴趣快筛；推荐优先意图重合，卡面标「契合」  
- 人卡：匹配理由 + 共同兴趣 chip + 侧栏打招呼（更高密度）  
- 预约：比价排序 + 连续列表；货架分区对齐 DiscoverBrowseSection  
- 顶栏 glass 圆形筛选；去掉自造指标条 / 假组局 / 装饰描边  

### 后续（数据层）

- 热搜 / 城市热意图由服务端下发，客户端不写死类目树  
- 个性化排序；冷启动用附近 + 活跃，不用假场景
