# 坐标系 · 愿景（V1）

> 参考苹果「为人做体验」、谷歌「一句话说清组织什么、为何有用」的写法。  
> 本文件为**第一版正式愿景**；产品结构见 [AppArchitecture.md](AppArchitecture.md)。

---

## 1. 愿景（Vision）— V1 定稿

**让一起玩，变得简单、自然、可信。**

英文对照（对内 / 材料用）：

**Make playing together simple, natural, and trustworthy.**

### 为什么这样写

| 参照 | 我们学到什么 | 在本句中的落点 |
|------|--------------|----------------|
| **Google** | 一句完成时态目标：组织什么 → 对谁有用 | 「一起玩」= 组织的对象；「简单、自然、可信」= 有用标准 |
| **Apple** | 不堆功能，强调人的体验与信任感 | 「简单 / 自然」= 体验；「可信」= 敢约、约得成 |
| **产品现实** | V1 做场 + 人 + 沟通闭环，不做万能社交 | 动词落在「一起玩」，不是「连接所有人」；同城是落地场景，不必写进愿景句 |

---

## 2. 使命（Mission）— 愿景之下怎么做

愿景是方向；使命是 V1 每天在做什么：

**帮用户发现合适的活动、找到合适的搭子，并用消息与履约凭证，把「想一起」变成「约上了」。**

与关于页现有表述对齐：

> 发现活动、找到搭子，并把社区分享与消息串成一条闭环。

---

## 3. V1 边界（愿景不做什么）

第一版愿景**刻意收窄**，避免写成无法交付的口号：

| 我们承诺（V1） | 我们暂不承诺 |
|----------------|--------------|
| 「一起玩」的发现与成局（当前以同城落地） | 成为通用社交网络 / 内容平台 |
| 场（活动）与人（搭子）两条清晰路径 | 用少数场景磁贴覆盖所有生活 |
| 沟通与凭证支撑履约 | 用公开星级墙定义人格 |
| 简单、自然、可信的体验 | 「改变世界」「连接全人类」级表述 |

## 4. 一句层级（对外可选用）

按场合选用，勿混用：

| 层级 | 文案 | 用途 |
|------|------|------|
| **愿景** | 让一起玩，变得简单、自然、可信。 | 品牌、关于页、融资一页纸标题 |
| **使命** | 发现活动、找到搭子，把想一起变成约上了。 | 功能叙事、设计原则校验 |
| **搭子域** | 找人玩。 | 搭子 Tab / 增长话术 |
| **活动域** | 发现一场局 → 读懂 → 参加。 | 活动发现 / 设计系统 |

---

## 5. 自检（改文案时用）

任何新功能或营销句，问三句：

1. 是否让「一起玩」更**简单**？  
2. 是否让路径更**自然**（少猜、少空聊）？  
3. 是否让履约更**可信**（敢约、约得成、有据可查）？  

三问都答不上 → 与 V1 愿景无关，不宜作为主叙事。

## 6. 修订约定

- **V1 愿景句锁定**上文加粗中文句；英文为对内翻译，可随本地化微调。  
- 重大改版（例如从「一起玩」扩到「通用生活服务」）升为 **V2**，并同步改关于页、[PRD.md](PRD.md) 与 `AppArchitecture.md`。  
- 设计与交互仍以 `DESIGN_SYSTEM.md` 为准：原生、克制、转化优先——那是愿景里「自然」的实现方式。
